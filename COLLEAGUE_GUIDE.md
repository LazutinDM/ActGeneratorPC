# Справочник разработчика ActGeneratorPC

Этот документ объясняет устройство проекта и показывает, где безопасно менять
поведение программы. Он дополняет комментарии `COLLEAGUE EDIT POINT` в коде.
Комментарии к каждой очевидной строке намеренно не добавляются: они дублируют
Python-код, быстро устаревают и затрудняют проверку изменений. Вместо этого здесь
описаны назначения модулей, последовательности действий и обязательные условия.

## Главное правило portable

`ActGeneratorPC.exe` нельзя отделять от папки `Data`. В `Data` одновременно
находятся runtime Python/Qt и ресурсы программы. Пользовательские акты лежат в
`Acts`. Обновление обязано сохранять `Acts`, настройки, историю, списки и рабочую
Excel-книгу.

## Карта проекта

Каждая функция и метод в рабочих Python-модулях содержит docstring сразу после
заголовка `def`. Это краткое описание назначения функции, а не пересказ каждой
строки. Перед изменением функции прочитайте её docstring, комментарии
`COLLEAGUE EDIT POINT`, вызывающие её тесты и соседние функции в том же разделе.

Проверка документации запускается командой:

```powershell
python tools/check_function_docs.py
```

Если добавлена новая функция, команда завершится ошибкой до тех пор, пока у неё
не появится описание. `python tools/check_function_docs.py --fix` добавляет
начальный вариант docstring, который нужно уточнить для бизнес-правил.

### `app.py`

Главный модуль интерфейса. Он:

1. создаёт основное окно и поля формы;
2. загружает текстовые списки и реестр оборудования;
3. связывает станцию, заводской номер и тип оборудования;
4. выбирает DOCX-шаблон;
5. формирует одиночные и массовые акты;
6. управляет предпросмотром и локальной историей;
7. запускает проверку обновлений после успешного старта.

Основные области:

- константы в начале файла — форматы полей, исключения и таблица псевдонимов;
- функции `normalize_*` — очистка пользовательского и табличного текста;
- `load_equipment_registry` — проверка и загрузка привязок из JSON;
- небольшие классы полей — календарь, время, выпадающие списки и счётчик;
- `MainWindow._build_*` — построение меню, формы, очереди и истории;
- `refresh_serials_for_station` — фильтр номеров по выбранной станции;
- `apply_equipment_for_serial` — заполнение оборудования по точному номеру;
- `pick_template_for_equipment_type` — выбор DOCX-шаблона;
- `_collect_form_data` и `_apply_form_data` — обмен данными формы;
- создание акта в нижней части класса — заполнение DOCX, Excel и истории.

### `app_paths.py`

Единственный источник путей. Здесь задаются папки, имена иконок, списков,
шаблонов и конфигурации. Не добавляйте абсолютные пути конкретного компьютера.
В режиме разработки корнем является папка исходников; в portable — папка EXE.

### `excel_export.py`

Отвечает только за XLSX:

- выбирает встроенную или пользовательскую книгу;
- восстанавливает отсутствующий/пустой встроенный шаблон;
- находит первую свободную строку;
- записывает разрешённые колонки;
- не меняет `Проверил`, `Наличие акта` и `Заявка`;
- создаёт резервную копию книги перед записью.

Правила участков и примечания меняются в константах с отметкой
`COLLEAGUE EDIT POINT`. После изменения обязательно запускайте
`tests/test_excel_export.py`.

### `history_store.py`

Хранит один JSON рядом с историей для каждого созданного акта. Это исключает
конфликт единого файла при аварийном завершении. История показывает только
существующие DOCX; удалённый из `Acts` документ исчезает после обновления списка.

### `docx_preview.py`

Преобразует временный DOCX в PDF через установленный Word или LibreOffice.
PDF нужен только для визуального предпросмотра и удаляется вместе с временной
папкой. Ошибка предпросмотра не должна удалять заполненные пользователем поля.

### `update_manager.py`

Выполняет безопасное обновление:

1. читает конфигурацию Release;
2. скачивает ZIP во временную папку;
3. проверяет структуру и запрещает выход путей из каталога распаковки;
4. создаёт резервную копию программы;
5. заменяет файлы;
6. ждёт подтверждение успешного запуска;
7. при отсутствии подтверждения автоматически возвращает резервную копию.

Никогда не добавляйте в обновление удаление `Acts` или пользовательской Excel.

### `tools/extract_google_registry.py`

Создаёт JSON-реестр из экспортированной XLSX-книги. Скрипт не изменяет исходную
таблицу. Номера должны быть уникальными. Если один номер относится к разным
станциям или моделям, скрипт завершает работу ошибкой вместо случайного выбора.

### `equipment_registry_update.py`

Содержит рабочую логику кнопки «Обновить станции и оборудование из таблиц» в
меню «Файл». Модуль скачивает публичный XLSX-экспорт утверждённой Google-таблицы,
читает только листы `МКТФ`, `Валидатор ВП-FT` и `БПА`, проверяет структуру и
уникальность номеров, затем атомарно заменяет `station_serials.json`. Предыдущая
версия сохраняется как `station_serials.previous.json`. Если скачивание, формат
или проверка данных завершаются ошибкой, установленный реестр не изменяется.

Список станций берётся из `location_list.txt` и обрывается на `АЛАБУШЕВО`.
Удалённая таблица не может самостоятельно добавить в интерфейс станции ниже
этой границы. Написания `Зеленоград-Крюково` и `Зеленоград Крюково`
нормализуются в `КРЮКОВО`.

## Привязка оборудования

Источник может содержать исторические написания и опечатки. Интерфейс всегда
использует точные значения из `Data/Variables/model_list.txt`:

| Значение источника | Значение программы |
| --- | --- |
| `АБП-БН` или `АПБ-БН` | `АБП-БН` |
| `АБП` или `АПБ` | `АБП-09` |
| `АН-15` или `АН 15` | `АН-15` |
| `БПА-20-БН1` | `БПА-20-БН1` |
| `АБП-09-М3` или `АПБ-09-М3` | `АБП-09-М3` |
| `МКТФ` | `МКТФ` |

Одинаковая таблица правил находится в `EQUIPMENT_MODEL_ALIASES` (`app.py`) и
`MODEL_ALIASES` (`tools/extract_google_registry.py`). При добавлении нового
псевдонима меняйте обе таблицы и тест.

Последовательность работы интерфейса:

1. пользователь выбирает станцию и тип оборудования;
2. `refresh_serials_for_station` оставляет номера, одновременно соответствующие
   выбранной станции и выбранному типу оборудования;
3. при пустом типе оборудования показываются все номера выбранной станции;
4. пользователь выбирает или вручную вводит номер;
5. сигнал поля вызывает `apply_equipment_for_serial`;
6. функция ищет точное совпадение нормализованного номера;
7. программа заполняет модель и подтверждает найденную станцию;
8. неизвестный номер остаётся доступен для ручного ввода и не меняет поля.

## Текстовые списки

Файлы в `Data/Variables` имеют UTF-8 и содержат по одному значению в строке:

- `executor_list.txt` — исполнители;
- `location_list.txt` — станции;
- `model_list.txt` — канонические названия оборудования;
- `work_list.txt` — виды выполненных работ;
- `done_work_list.txt` — подробные формулировки выполненной работы;
- `issues_list.txt` — несоответствия;
- `materials_list.txt` — материалы и запчасти;
- `station_serials.json` — станция/номер/оборудование.

Не ставьте точку в конце элементов `done_work_list.txt`, если она не является
частью требуемой формулировки. Не переименовывайте значения `model_list.txt` без
одновременной правки псевдонимов, выбора шаблона и тестов.

## Добавление или изменение поля формы

1. Создайте поле в блоке формы `MainWindow`.
2. Подключите сигнал только к функции, которая действительно должна реагировать.
3. Добавьте значение в сбор данных формы.
4. Добавьте обратную загрузку для истории и массовой очереди.
5. Добавьте замену плейсхолдера DOCX, если поле попадает в акт.
6. При необходимости добавьте колонку Excel, не затрагивая игнорируемые колонки.
7. Добавьте тест одиночного акта и тест загрузки данных обратно в форму.

## Чистый акт по фамилии

Кнопка `Акт по фамилии` содержит два действия для `ABP_MKTF.docx` и
`Validator_MID.docx`. Функция `executor_name_with_initials` очищает фамилию от
цифр и посторонних символов и нормализует найденные инициалы как `И. О.`.
Отсутствующие при ручном вводе инициалы функция не придумывает.
`create_surname_only_act` формирует отдельный набор данных: заполнена только
фамилия, остальные пользовательские поля пусты. Такой DOCX сохраняется в
историю, но намеренно не записывается в Excel. Составной плейсхолдер
`{MODEL} № {SERIAL}` очищается целиком, чтобы в пустой строке оборудования не
оставался отдельный знак `№`.

## Изменение DOCX-шаблонов

Сохраняйте имена плейсхолдеров и проверяйте их во всех таблицах, абзацах,
колонтитулах и текстовых блоках. Для MID/Валидатора период услуги является
необязательным: пустые поля не должны запрещать создание акта. Дата периода
берётся из основного поля `Дата`, пользователь вводит или выбирает только время.

## Проверка перед сборкой

Запустите:

```powershell
python -m compileall -q .
python -m unittest discover -s tests -v
.\build.ps1 -SkipInstall
```

После сборки обязательно:

1. запустите EXE из `dist/ActGeneratorPC`;
2. выберите станцию и несколько номеров разных типов;
3. проверьте одиночный акт;
4. проверьте массовую очередь при включённом режиме;
5. убедитесь, что без включения режима очередь не видна;
6. проверьте открытие истории и DOCX;
7. проверьте запись в копию Excel;
8. закройте приложение и убедитесь, что оно запускается повторно.

## Git

Не добавляйте в коммит `build`, `dist`, `.idea`, `.vs`, `__pycache__`, резервные
папки, пользовательские акты и рабочую Excel-книгу. Перед добавлением файлов
проверяйте `git status`; не используйте `git add -A` в грязном рабочем дереве.
